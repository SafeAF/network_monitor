# Security and improvement plan

Review date: November 11, 2026.

This review covers the Rails application, Go agent, ingestion contract, deployment files, and test configuration. The highest priorities are access control, stored cross-site scripting (XSS), and trustworthy ingestion. A LAN deployment still needs these protections: any compromised device that can reach the app currently has access to its investigation and alert-management functions.

This is a source review, not a penetration test or a completed dependency vulnerability scan. Deployed proxy, firewall, TLS, and scheduling settings were not inspected. At the initial review, only this plan was added. The status below records subsequent implementation work.

## Second implementation batch — November 12, 2026

Implemented the next R1/S4/O1 changes:

- [Event validation](../../netmon/app/lib/netmon/event_contract.rb) allows only the supported event types, literal IPs, bounded ports/protocols/counters, valid RFC 3339 timestamps, bounded nesting/strings/DNS answers, and objects with the expected shape. Limits are 500 events per batch, 32 KiB per event, and a 30-day replay window with five minutes of future clock skew. `heartbeat` and `firewall_drop` are explicitly raw-only.
- [A middleware guard](../../netmon/lib/netmon/request_body_limit.rb) limits request bodies to 4 MiB before Rack method override or Rails parameter parsing, including requests whose declared length understates the body. This limit applies to all app requests.
- [Batch processing](../../netmon/app/lib/netmon/batch_ingest.rb) uses a separate transaction per event. A receipt and its normalized changes commit together. Failures in strict DNS persistence/backfill/domain linking now propagate to that boundary. Results distinguish `accepted`, `duplicate`, `rejected`, and `retryable`; duplicate outcomes count toward `accepted` for compatibility.
- [The migration](../../netmon/db/migrate/20261112120000_add_ingest_event_identity.rb) adds a router/event identity uniqueness constraint and a content digest. New agents allocate random event IDs before queueing and preserve them through retries. Older events without IDs use a canonical payload/timestamp digest; immutable retries with the same identity cannot repeat normalized writes. Reusing an identity with different content is rejected. Historical receipts remain nullable and are not retroactively deduplicated.
- [The agent transport](../../netmon_agent/internal/httpclient/client.go) requires a versioned, complete acknowledgement with consistent indices, statuses, and counts before removing a batch. It advertises `X-Netmon-Protocol-Version: 1`. Legacy clients that do not inspect response bodies receive 503 on any partial failure, retaining their batch for retry until upgraded. Oversized new batches are split before sending.
- [Spool persistence](../../netmon_agent/internal/spool/spool.go) uses private temporary files, file sync, atomic rename, and directory sync on Linux. Startup recovers complete pre-rename writes and quarantines incomplete ones. Permanent rejections retain their payload and server acknowledgement in `quarantine_*.json`; corrupt pending JSON is quarantined before moving to subsequent batches. The pending queue reserves 90% of `spool_max_bytes`, quarantine 10%, and each partition is capped at 10,000 files. Evictions are logged. A directory must have one owning agent process.
- Oversized legacy spool files are retained intact with an explicit error and require operator recovery; they are never acknowledged from a truncated read. Quarantine write/capacity failures likewise retain the pending original. This can block that queue until an operator resolves the condition. Quarantine is bounded diagnostic retention, not permanent archival storage.
- Older observations no longer regress existing flow counters or device/host/domain last-seen timestamps. Flow lifetime/tuple reuse, first-observation byte semantics, and router scoping of normalized records remain R4 work.
- [Host enrichment](../../netmon/app/jobs/host_enrichment_job.rb) runs after ingest commit, outside the ingest write transaction. Requests are throttled per host to once per five minutes while metadata is due. Reverse DNS has a deadline and WHOIS has bounded output, termination, and reaping. Enrichment remains best effort; durable dispatch is follow-up work under R2/operations. The third batch adds score refresh after new metadata.
- [Raw receipt retention](../../netmon/app/jobs/prune_netmon_events_job.rb) runs every minute in production and deletes at most ten 1,000-row batches per run after 35 days, beyond the allowed replay window. This needs a running Solid Queue worker/scheduler; retention lag and cleanup for other telemetry tables still need operational monitoring.

Rollout order is required: back up the database and spool; deploy the updated Rails app and run `bin/rails db:migrate` in the intended environment; then upgrade the agent. A new agent talking to an old unversioned server retains batches rather than trusting incomplete acknowledgements. In production, run migrations with the production environment and existing credentials configured. No migrations were applied to a running installation here. The schema file was updated to match the migration because Rails execution is blocked locally.

Verification: **18 standalone tests, 88 assertions passed** across validation/body limits and the previous security utilities; Ruby source and CI/retention YAML parse; changed Go files were parsed/formatted with the verified official `gofmt`. Added RSpec tests for duplicate replay, conflicting identities, transaction rollback, strict DNS failures, mixed batches, stale observations, legacy-client failures, size limits, and retention. Added Go tests for acknowledgement integrity, permanent/transient failures, replay/quarantine, private concurrent writes, crash recovery, oversized-file preservation, and path containment. RSpec, migrations, Brakeman, and Go tests remain unexecuted locally because of the Windows dependency/tool execution restrictions recorded above; Linux CI remains a release gate.

Still open: per-router quotas and credential binding, full flow lifetime/accounting semantics, detection parity and score refresh, DNS log rotation, durable enrichment dispatch, probe concurrency controls, CSP enforcement, dependency audits, and load/restore drills.

## Third implementation batch — November 12, 2026

Implemented R2/R3 detection and DNS collection changes, plus the Rails-side outbound filter from R4:

- [Shared detection](../../netmon/app/lib/netmon/anomaly/detection.rb) and [hit/incident recording](../../netmon/app/lib/netmon/anomaly/recorder.rb) now serve both agent and snapshot ingestion. Scores use the current persisted minute deltas; accepted nonstale flow observations, including DESTROY updates, are rescored. Existing allowlist, suppression, device-level fanout/scan, alert threshold, and incident fingerprint policies are retained. Incident failures roll back agent receipts and normalized writes together.
- Recording acquires a per-device database write lock before checking cooldowns. Cooldowns cover nearby late observations, incident matching checks both ends of the event-time window, and late hits extend first-seen time without regressing last-seen time. Receipt identity still stops exact replay before detection runs. Connection counts, byte attribution, tuple reuse, and router scoping remain separate R4 work.
- Device statistics count distinct recently first-observed destinations from persisted connections/hosts rather than summing snapshot-only novelty counters. Statistics and ASN history exclude future observations relative to event time. The scored connection and same-timestamp peers do not hide a newly encountered ASN. Agent minute novelty counters and baseline calibration still need reconciliation under R4.
- [Outbound filtering](../../netmon/app/lib/netmon/filter.rb) is shared by both Rails paths. The default requires an original source in 10.0.0.0/24 and excludes configured destination networks. Out-of-scope agent observations remain raw receipts and do not create internal devices, normalized flows, or incidents. Go collection still labels flows OUT without consuming its LAN configuration; collector-side option/direction semantics remain open.
- [Enrichment score refresh](../../netmon/app/jobs/host_score_refresh_job.rb) scans at most 100 connections per job with a fixed ID endpoint and bounded continuation jobs. Only connections observed within the past ten minutes are rescored, using their event time; traffic deltas and counts are not applied again. Enrichment retries can redispatch scoring after a previous metadata save. This requires a working job queue; a durable dispatch/outbox and periodic live-flow sampling remain open.
- [DNS tailing](../../netmon_agent/internal/dns/dnsmasq_tail.go) compares the configured path's identity with the open file, drains the old file before opening replacements from byte zero, follows rename/create gaps, detects shorter copy-truncations, and retains incomplete lines. Existing history is skipped only on the first startup attempt; a file created after startup is read from its beginning. Fragments from different files are never joined. Lines are capped at 16 KiB, and each drain processes roughly 1 MiB before yielding and checks cancellation between chunks.
- A 64-byte checkpoint also detects many truncate/regrow cases. This is a heuristic: regrowth that reproduces the checkpoint can escape detection, and offsets are not persisted across process restarts. Rotation still requires the writer to finish the old file before it is drained/closed. These changes do not promise lossless collection across arbitrary filesystem races or downtime.
- [DNS parsing](../../netmon_agent/internal/dns/parse.go) bounds fields and validates client IPs, with sample-based tests. December logs followed in January use the preceding year rather than a timestamp nearly a year in the future. [Correlation](../../netmon_agent/internal/dns/correlate.go) caps pending queries at 4,096, client contexts at 2,048 (30-minute expiry), aliases at 16 per query, and answers at 64. Overflowed queries are dropped whole rather than emitted with truncated answers. Cleanup clears stale references and compacts backing arrays. Closed input stops the consumer, and emitted-response metrics increase only after successful queue admission. Existing ambiguous same-name/alias fallback attribution remains R4 work.
- Agent metrics now expose DNS log rotations/truncations, tail read failures, and the last complete line read. Existing local-drop metrics distinguish line overflow, partial lines, query/cache/answer/alias limits, expiry, and queue backpressure. Reading a line is collection health, not proof of successful parsing, delivery, or per-router application processing; the global heartbeat UI still needs that distinction.

Added RSpec coverage for real scorer/policy behavior through agent requests, snapshot parity, terminal high egress, allowlists/suppression, WAN-source filtering, fanout, enrichment refresh without double counting, bounded refresh continuation, late incident grouping, same-timestamp ASN peers, event-time statistics, retry dispatch, and rollback. ## Fourth implementation batch — November 12, 2026

Implemented single-router containment and stricter DNS attribution from R4:

- This installation now explicitly supports **one router** while devices, flows, host-domain links, rules, and incidents retain global IP-based identities. Set NETMON_ROUTER_ID to the exact router_id used by its agent. [Router policy](../../netmon/app/lib/netmon/router_policy.rb) checks this identity separately from bearer authentication. A token holder cannot submit another declared router identity, but a stolen token can still impersonate the configured router; credential rotation/revocation remain open.
- [A persistent singleton binding](../../netmon/app/lib/netmon/router_scope.rb) prevents an environment change or receipt retention from silently assigning existing normalized data to a different router. The first successfully committed event establishes the binding in the same transaction as its receipt and normalized writes. Failed/invalid events do not claim it. The primary key and database check constraint prevent separate concurrent bindings. Snapshot ingestion also requires the configured identity and establishes the same binding before normalization. Snapshot files/commands must come from that router; the application cannot verify a file's physical origin.
- [The migration](../../netmon/db/migrate/20261112130000_bind_single_ingest_router.rb) preserves a single router ID found in historical raw/DNS records. It stops before changing tables if it finds multiple or invalid historical IDs, requiring an audit and separation of existing data. It never guesses ownership or rewrites previously merged normalized data. If historical identifying records are already absent, configure the router that actually owns the existing installation before the first binding. An existing installation's ownership still needs operator verification.
- Missing/invalid router configuration and a conflict with the stored binding return 503 with retryable: true, retaining agent batches. A different declared router receives 400/router_mismatch before receipts or normalized changes. Updated agents quarantine permanent rejection payloads under their existing bounded quarantine policy; older agents retain non-2xx batches for retry. Kamal now forwards NETMON_ROUTER_ID from its environment reference.
- [DNS lookup](../../netmon/app/lib/netmon/dns/correlate_connection.rb) now requires the same router and client, an A/AAAA query, a successful response, and an observation within the ten minutes preceding the flow observation, inclusive. Future observations no longer label replayed flows. Expired/future cached flow-domain labels are refreshed or cleared on the next accepted nonstale flow observation.
- [DNS backfill](../../netmon/app/lib/netmon/dns/backfill_connections.rb) applies the same router/client/successful-forward-answer restrictions. A late-delivered DNS observation can label only flow observations at or after its event time and within ten minutes. The former 30-second allowance for DNS observed after the flow was removed. PTR observations remain available as DNS data and no longer become application-domain attribution for client traffic. Historical host-domain links are not rewritten by this batch.

Rollout: back up the database, verify the owning router, set NETMON_ROUTER_ID in both web and worker/snapshot environments to match the agent configuration, and run bin/rails db:migrate before enabling updated ingestion. Run the migration in the intended Rails environment. If mixed historical router IDs stop the migration, audit/separate those datasets; changing the binding or deleting history to force a choice can hide earlier cross-router merging. No migration, deployment, or historical data cleanup was performed here.

Added/updated RSpec tests for singleton database enforcement, binding persistence after pruning, configuration conflicts, mismatched router requests, invalid/rolled-back events, snapshot rejection, same-client/event-time DNS matching and backfill, PTR exclusion, and expired cached labels. ## Fifth implementation batch — November 12, 2026

Implemented agent lifetime counter accounting from R4:

- [Persistent lifetime state](../../netmon/app/lib/netmon/flow_lifetimes.rb) separates cumulative counter high-water marks from the latest five-tuple projection shown in the UI. The ledger, receipt, normalized rows, rollups, and detection commit or roll back together. Counter fields are nonnegative in the database, and router/lifetime identities have a uniqueness constraint.
- [Accounting](../../netmon/app/lib/netmon/flow_accounting.rb) credits the full first observed byte/packet totals, including destroy-only flows, into the observation's minute bucket. Later observations credit only increases. Missing optional counters preserve their previous values. Agent minute connection counts and host-port seen counts increase once per recognized lifetime, rather than once per NEW/DESTROY event. This is observed traffic attribution; bytes are not interpolated across the unknown lifetime duration.
- The event contract now accepts an optional bounded flow_id, distinct from the receipt id. A producer must keep it immutable for a single lifetime, preserve it across retries/restarts, and allocate a different identity for another lifetime, including counter resets. Explicit identities cannot change their tuple. Counter regression or reopening a closed explicit identity is a permanent structured rejection (with the existing agent quarantine behavior), rather than lowering a baseline and double counting a later increase.
- The current Go collector still does not emit flow_id. Its compatibility path recognizes NEW followed by DESTROY and starts another lifetime on a later NEW after closure. A late NEW can match a provisional destroy-only lifetime without counting it again. Repeated terminal observations with unchanged counters do not repeat traffic totals, even under different receipt identities. This fallback cannot resolve arbitrary missing/reordered lifecycle markers, reused tuples with destroy-only observations, or rapid same-clock-tick reuse. Such ambiguities remain open; this batch does not claim robust identities from the current collector.
- Existing legacy projection counters can seed the first post-migration lifetime baseline so already attributed traffic is not credited again. Historical missing first-observation bytes, duplicate counts, and incorrect tuple attribution are not repaired. Switching an in-flight legacy stream to explicit flow IDs requires a controlled accounting boundary; the server cannot prove that a new explicit ID corresponds to a previous unidentified lifetime.
- A separately identified older lifetime can finish late, update its own counters and rollups, and create hits/incidents without overwriting a newer flow's current connection row or score. Reused tuples reset the projected first-observed time and cached DNS association. Completed flows are projected as DESTROY even when the collector also supplies an established TCP state. Normalization compares event times at the database's microsecond precision; raw receipt digests retain their original timestamp precision.
- [Collector binding](../../netmon/app/lib/netmon/router_scope.rb) now persists agent versus snapshot flow collection alongside the router binding. The first successful flow claim wins. The other collector cannot apply traffic rollups to that installation; agent batches remain retryable on a conflict, and snapshot ingestion raises an explicit configuration error. DNS and heartbeat ingestion do not claim a flow collector. Snapshot accounting retains its existing sampling semantics; it is not converted into lifetime accounting here.
- Closed lifetime high-water marks are retained for 35 days after their last observation, beyond the 30-day replay window, then removed in at most ten 1,000-row batches by the existing scheduled retention job. Open lifetime records are retained because absence of updates does not establish that a long-running flow has ended. Missed DESTROY events can therefore accumulate open state; safe cleanup requires collector reconciliation/live sampling and operational storage monitoring.

Rollout: back up the database and spool, stop the unused flow collector, and run the [new migration](../../netmon/db/migrate/20261112140000_add_agent_flow_lifetimes.rb) before starting the updated app/worker. It adds the ledger, projection identity, and persisted collector choice. Keep the existing NETMON_ROUTER_ID configuration. A collector choice must not be reset casually to switch counting models over the same data. Establish a controlled accounting boundary for collector/identity changes, and recalibrate baselines after sufficient new-format observations rather than treating old event-count baselines as directly equivalent. No migration, deployment, or historical repair was performed here; schema.rb was updated to match the migration because Rails cannot execute locally.

Verification: **31 standalone tests, 143 assertions passed**, including eight new accounting tests and the expanded event contract suite. All 18 changed/new Ruby files compile, CI YAML parses, and whitespace checks pass. Added request-level RSpec cases for NEW/DESTROY totals, destroy-only data, distinct receipt identities, tuple reuse, explicit identity conflicts, counter regressions, late completion accounting/detection without projection changes, stale events, atomic rollback, and collector conflicts; added closed/open ledger retention and collector-binding tests. RSpec, migrations, and Linux end-to-end tests remain unexecuted locally because of the recorded Windows runtime restrictions. Linux CI remains a release gate. No Go source changed.

Next R4 work: produce restart-safe lifetime IDs in the agent, reconcile active flows and missing events, honor LAN/direction and NEW-emission configuration, and align minute novelty counters/baseline definitions. Primary-source inspection confirmed that the current [conntrack library exposes a kernel ID and timestamp field](https://raw.githubusercontent.com/ti-mo/conntrack/v0.6.0/flow.go), while the [kernel describes its ID as almost unique](https://raw.githubusercontent.com/torvalds/linux/v6.12/net/netfilter/nf_conntrack_core.c); neither a raw 32-bit ID nor per-event wall-clock first_seen is a complete lifetime identity strategy. The generation, boot/namespace, restart, and missing-event cases must be addressed together. ## Findings and recommended changes

### S1 — High: web UI and management actions have no application authentication

Evidence: [ApplicationController](../../netmon/app/controllers/application_controller.rb#L1) only applies browser-version checks. [Routes](../../netmon/config/routes.rb#L17) expose telemetry, device updates, incident acknowledgements, allowlists, and suppression creation. Their controllers do not require a signed-in user or check roles. Authentication is confined to the agent batch endpoint.

Impact: a client that can reach Rails can read network activity, change labels, acknowledge incidents, and create rules that reduce detection. Rails CSRF protection does not establish a user's identity; a direct client can obtain its own session and authenticity token.

Plan: require operator authentication for HTML and JSON routes; distinguish read access from alert/rule administration. For a small installation, an authenticating reverse proxy is a reasonable first containment step if direct access to Rails is blocked. Keep agent authentication separate. Record actor, time, target, and changes for acknowledgements and rule updates. Bound rule/name/note lengths.

Acceptance: anonymous reads and writes are rejected; readers cannot mutate rules or incidents; an agent credential cannot open operator pages; authorized changes create audit records.

### S2 — High: stored values become executable dashboard HTML

Evidence: the dashboard interpolates device names into an input attribute at [line 613](../../netmon/app/views/dashboard/index.html.erb), domains into link text and attributes at [line 593](../../netmon/app/views/dashboard/index.html.erb), and reverse-DNS/WHOIS values at [line 637](../../netmon/app/views/dashboard/index.html.erb). The resulting strings reach `innerHTML` at [line 701](../../netmon/app/views/dashboard/index.html.erb). Top panels also insert device labels into HTML at [line 1556](../../netmon/app/views/dashboard/index.html.erb). [DevicesController](../../netmon/app/controllers/devices_controller.rb#L8) accepts names without content restrictions. The [CSP initializer](../../netmon/config/initializers/content_security_policy.rb#L1) is entirely commented out.

Impact: a crafted stored name can execute JavaScript when an operator views the dashboard. Telemetry, DNS, and enrichment strings provide additional untrusted inputs. A device name containing HTML is a sufficient source-level reproduction path; exploitation through real DNS depends on resolver/log formatting and was not tested.

Plan: replace dynamic HTML templates with DOM creation, `textContent`, and property assignment such as `input.value`; encode URL path components and construct URLs with URL APIs. Review every `innerHTML` sink, including drilldowns and incident panels. Move inline dashboard JavaScript into maintained modules and introduce a restrictive CSP, initially in report-only mode. CSP supplements safe rendering.

Acceptance: browser tests persist markup and quote-containing names and ingest hostile metadata; refresh, detail panels, and drilldowns display literal text without creating executable elements or event handlers.

### S3 — High when HTTP is used: agent token and telemetry travel in cleartext

Evidence: [the checked-in sample config](../../netmon_config.yaml#L3) and [agent setup guide](../../netmon_agent/docs/AGENT_SETUP.md#L16) use HTTP. [Config validation](../../netmon_agent/internal/config/config.go#L111) only checks that URL and token are nonempty. The [HTTP client](../../netmon_agent/internal/httpclient/client.go#L211) sends a reusable bearer token. The sample also contains fixed placeholder token/salt values; their presence is not evidence of a leaked live credential.

Impact: on an observable or manipulated network path, tokens and DNS/flow activity can be captured or altered. Rails production SSL settings do not protect the initial plaintext request sent by the agent.

Plan: require HTTPS and certificate verification by default, with a clearly named development-only HTTP override. Reject placeholder credentials outside development; use strong random credentials. Add per-router credentials, revocation, overlapping rotation, and binding between credential and `router_id`. Use constant-time secret comparison as secondary hardening. Restrict redirects to the intended HTTPS origin. Add `NETMON_API_TOKEN` to deployment secret wiring: [deploy.yml](../../netmon/config/deploy.yml#L35) currently injects only `RAILS_MASTER_KEY`.

Acceptance: HTTP, invalid certificates, redirects outside the configured origin, missing credentials, and unauthorized router identities fail; valid HTTPS ingestion and credential rotation succeed.

### S4 — High with an agent credential: ingest can consume excessive resources

Evidence: [EventsController](../../netmon/app/controllers/api/v1/netmon/events_controller.rb#L5) accepts an unbounded event collection and arbitrary nonempty event types. Flow [IP fields](../../netmon/app/lib/netmon/agent_ingest.rb#L21) receive presence checks, not IP validation; ports, counters, and timestamps lack domain bounds. Each batch opens one database transaction. [Host enrichment](../../netmon/app/lib/netmon/agent_ingest.rb#L42) performs DNS and WHOIS inside that transaction, and [WHOIS execution](../../netmon/app/lib/netmon/host_enricher.rb#L68) has no application timeout.

Impact: a stolen credential, a noisy network, or malformed agent data can fill storage, occupy web workers, and extend SQLite write contention. Invalid IP strings also reach external utilities as arguments. Argument arrays avoid ordinary shell interpolation, but destination and option validation are still necessary.

Plan: enforce request byte limits at the proxy and application boundary, event-count and field-size limits, supported event types (including the agent's `firewall_drop` type), object/array shapes, literal IP addresses, valid port/protocol ranges, nonnegative bounded counters, and a documented timestamp/replay window. Add per-router quotas. Reject unknown types or explicitly classify them as raw-only; do not call them normalized successes. Move enrichment to bounded jobs outside write transactions, with deadlines, output limits, caching, and safe utility arguments.

Acceptance: oversized requests receive 413; invalid events receive structured errors; malformed event shapes never cause an unhandled 500; slow enrichment does not extend ingest transactions. Load tests show bounded memory and acceptable UI latency during ingestion.

### S5 — Medium: traceroute can be triggered through an unauthenticated GET

Evidence: [the route](../../netmon/config/routes.rb#L35) uses GET; [the action](../../netmon/app/controllers/remote_hosts_controller.rb#L69) enqueues work when `start` is present and accepts cancellation through query parameters. [TracerouteJob](../../netmon/app/jobs/traceroute_job.rb#L20) passes an unvalidated route parameter to the utility. Host detail views similarly invoke `geoiplookup` with the supplied value.

Impact: a reachable client can enqueue network probes to arbitrary accepted destinations, consume worker capacity, and trigger state changes through cross-origin GET requests. The current argument-array calls do not establish shell-command injection. String values beginning with options and arbitrary hostnames should still be excluded.

Plan: use authenticated, authorized POST/DELETE operations with CSRF protection for browser actions. Accept only literal IPs, require an explicit destination policy appropriate to LAN monitoring, deduplicate jobs atomically, and apply per-user/global concurrency and rate limits. Enforce child-process deadlines with termination and reaping; cancellation must stop work rather than only change a cached label. Keep result polling read-only.

Acceptance: GET never starts/cancels probes; anonymous requests, invalid destinations, options, and quota violations are rejected; timed-out and cancelled probes leave no running child process.

### R1 — High monitoring risk: rejection handling and replay can lose or corrupt data

Evidence: [EventsController](../../netmon/app/controllers/api/v1/netmon/events_controller.rb#L14) inserts raw data, then rescues per-event failures inside the outer transaction without a per-event rollback boundary. [DNS ingestion](../../netmon/app/lib/netmon/dns/ingest_event.rb#L15) returns nil on invalid input or errors, yet the controller increments `accepted`. The [existing request spec](../../netmon/spec/requests/api/netmon_events_spec.rb#L55) even expects malformed DNS plus a valid flow to report two accepted events. The [agent](../../netmon_agent/internal/httpclient/client.go#L230) discards response bodies, treating every 2xx as complete success, and [removes replayed spool files](../../netmon_agent/internal/httpclient/client.go#L263). Raw events have no event-identity uniqueness constraint.

Impact: rejected normalized events are silently abandoned; failures after early writes can leave partial normalized state. A timeout after server commit causes retry and duplicate raw events. Flow counters, per-minute connection counts, and reused flow tuples can be affected by duplicates or reordered live/replay delivery.

Plan: define stable event IDs and a durable acknowledgement contract before changing retry behavior. Atomically persist raw event identity and processing state; use per-event savepoints or an asynchronous durable inbox. Return per-event outcomes and separate retryable failures from permanent invalid input. Make normalized processing idempotent, retain retryable events, and put permanent failures in a bounded quarantine. Preserve order/version checks per flow so older replay cannot overwrite newer state. Add atomic spool writes using temporary files and rename, crash recovery, observable eviction, and corrupt-file quarantine so a bad oldest file cannot block all replay.

Acceptance: repeat a batch after a simulated commit-time timeout; raw identity, rollups, and incidents are unchanged by replay. A mixed batch reports accurate outcomes. Injected mid-event failures roll back that event. Partial rejection, corrupt spool files, restart during a write, and replay/live reordering do not silently lose valid events.

### R2 — High monitoring risk: the preferred agent path does not create incidents

Evidence: [AgentIngest](../../netmon/app/lib/netmon/agent_ingest.rb#L92) calculates and stores connection scores, but does not create `AnomalyHit` or `Incident` records. That workflow exists in [ReconcileSnapshot](../../netmon/app/lib/netmon/reconcile_snapshot.rb#L218), the alternate snapshot path. Agent rescoring also skips ordinary destroy updates once a score is present.

Impact: agent-only operation can show scored connections while anomaly and incident views remain empty or incomplete. Behavior that becomes apparent only after a flow accumulates traffic may not be rescored at termination.

Plan: extract shared detection, suppression, hit, and incident logic used by both ingestion paths. Re-evaluate at appropriate lifecycle points and/or periodically for active traffic, while retaining cooldowns and deduplication. Make heartbeat status distinguish transport health from successful flow/DNS processing; the [current health indicator](../../netmon/app/lib/netmon/metrics.rb#L18) only checks heartbeat arrival globally.

Acceptance: the same fixture produces equivalent expected detections through snapshot and agent ingestion. A high-volume completed flow produces the expected alertable hit/incident. One healthy router cannot hide another router's stalled collector.

### R3 — High monitoring risk: DNS log rotation can stop collection

Evidence: [Tail](../../netmon_agent/internal/dns/dnsmasq_tail.go#L57) checks `file.Stat()` on the already-open descriptor against its original inode. Renaming that file does not change its inode, so a replacement at the configured path is not detected. Copy-truncation is not handled. `ReadString` fragments received with EOF are discarded; reopening always seeks to the end.

Plan: compare the configured path's file identity with the open descriptor, detect truncation, retain incomplete lines, and define startup/reopen offset behavior. Bound line lengths and expose read errors, rotation events, and last successful DNS processing. Bound pending queries and expire inactive client entries in the correlator, whose client cache currently has no eviction.

Acceptance: Linux integration tests cover rename-and-create rotation, copytruncate, partial writes, missing/recreated files, oversized lines, and shutdown. Queries continue to appear after each rotation without unintended gaps or duplicates.

### R4 — Medium now; high for multiple routers: identity and flow accounting are underspecified

Evidence: [flow lookup](../../netmon/app/lib/netmon/agent_ingest.rb#L45) and the [unique connection index](../../netmon/db/schema.rb#L87) use only the five-tuple. Devices are identified by IP alone. Although ingestion receives `router_id`, these normalized keys and DNS correlation queries do not use it. The [agent](../../netmon_agent/internal/conntrack/conntrack.go#L64) labels every collected flow `OUT`; configured LAN interfaces/subnets and `emit_conntrack_new` have no consumers outside config declaration. [First-observation deltas](../../netmon/app/lib/netmon/agent_ingest.rb#L206) are zero, including a destroy-only observation, and connection counts increase for every event.

Impact: overlapping subnets on different routers merge devices and flows; inbound flows can be classified as outbound; missing NEW events undercount traffic; NEW/DESTROY updates count as separate connections. Reused tuples can inherit stale first-seen and DNS state. DNS correlation also lacks an upper time bound, allowing future observations relative to a replayed flow.

Plan: define router/network scope, a flow-lifetime identity, event ordering, counter-reset handling, and the meaning of connection counts. If only one router is supported initially, enforce that limitation. Implement source subnet/direction filtering and either honor or remove unused options. Bound DNS association by router, client, observation time, and a defined expiry/fallback policy; reverse DNS is supporting metadata rather than proof of the application hostname.

Acceptance: fixtures cover two routers with overlapping addresses, inbound/outbound IPv4 and IPv6, NEW plus DESTROY, destroy-only, tuple reuse, duplicate/reordered events, and stale/future DNS. Counts and byte totals match the documented semantics.

### O1 — Medium: retention does not bound all high-volume telemetry

Evidence: [cleanup](../../netmon/lib/tasks/netmon.rake#L24) removes selected rollups, anomalies, and incidents, but not `netmon_events` or stale connections. [DNS pruning](../../netmon/app/lib/netmon/dns/prune.rb#L12) is separate, and [recurring.yml](../../netmon/config/recurring.yml#L10) schedules only Solid Queue housekeeping. No supplied scheduler runs telemetry retention.

Plan: schedule bounded, indexed cleanup for raw events, DNS data, stale flows, metrics, and related records; document retention for identifying DNS and network activity. Prune DNS parents/children consistently, handle foreign-key relationships, monitor disk headroom, and test SQLite-aware backups and restoration. Budget time for database maintenance after deletes. Avoid logging entire batches; redact sensitive telemetry where practical.

Acceptance: expired records are removed in bounded batches without orphan records or prolonged write locks; fresh records remain. Disk/quota alerts fire, cleanup failures are visible, and a backup restores to a usable application.

### O2 — Medium: deployment and build configuration need consolidation

Evidence: the [recommended agent service](../../netmon_agent/deploy/systemd/netmon-agent.service#L7) runs as root without hardening; the [root-level alternative](../../netmon_agent.service#L20) has different paths and partial hardening. The [installer](../../netmon_agent_installer.sh#L23) resolves its repository root to the parent of its actual root-level location and expects absent example/config paths. Its build fallback uses predictable `/tmp/netmon-agent` as root. The [Docker build](../../netmon/Dockerfile#L37) uses Node 18 and downloads a moving `node-build` master archive to execute during the build. Node 18 is [end of life](https://nodejs.org/en/about/eol).

Plan: provide one supported installer/config/unit layout; use a private `mktemp` directory with cleanup for privileged builds. Prefer verifiable release artifacts, checksums, and reproducible builds. Constrain agent capabilities after testing netlink requirements, use read-only system/config access and narrowly writable state paths, and retain loopback metrics by default. Add metrics HTTP timeouts and a controlled shutdown that stops producers before closing channels, drains queues, and persists unsent data. Validate all numeric limits and durations. Update Node to a supported release and pin/verify build tooling. Configure production host allowlists and verify direct Rails access is restricted behind the intended TLS proxy.

Acceptance: install/upgrade works from a fresh checkout on supported Linux architectures; configuration is private, the agent can collect under the chosen capability restrictions, invalid settings fail clearly, and shutdown preserves queued work. Build inputs have documented versions and verification.

### O3 — High assurance gap: repository CI is misplaced and omits the actual test suite

Evidence: the Git repository root is `network_monitor`, but tracked workflow and Dependabot files live under [netmon/.github](../../.github/workflows/ci.yml#L1). GitHub requires workflows in the repository root's [`.github/workflows` directory](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax). The supplied test command runs Rails/Minitest while the meaningful suite is under `netmon/spec`; there are no Go jobs, dependency advisory audits, or DNS rotation/spool/client tests. Dependabot's configured `/` Bundler directory also does not match `netmon/` in this repository layout.

Plan: move GitHub configuration to the actual repository root and set Rails working directories explicitly. Run RSpec, Brakeman, a Ruby dependency advisory audit, JS dependency auditing, Go tests/race checks, `go vet`, and [govulncheck](https://go.dev/doc/security/vuln/) on Linux. Configure dependency updates for Bundler, JS, Go, and Actions with correct directories. Audit the locally replaced NFLOG module and record its upstream provenance; do not assume ordinary version scanning covers local changes. Build the production image and supported agent architectures in CI. Manage new audit dependencies explicitly when implementing this plan.

Acceptance: a pull request visibly runs each job, deliberately failing specs fail CI, and security failures have an owner and a time-bounded exception process. Record advisory results and actual reachable vulnerability findings before claiming dependencies are secure or vulnerable.

## Implementation sequence

Effort estimates are rough engineering days and include targeted tests; deployment constraints may change them. Execute as small reviewable changes, with database backups before identity/schema migrations.
